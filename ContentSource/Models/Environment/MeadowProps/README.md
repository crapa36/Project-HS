## Authorship, sources and rights

Geometry is generated locally by `tools/art/create_meadow_props_blender.py`, using the project's existing `Builder`, board, tube, sheet, material and export-validation helpers from `tools/art/create_ground_detail_blender.py`. No external mesh, purchased asset, generated-service result or third-party model was downloaded for these seven props. Original procedural geometry does not establish rights to every inherited texture; the source dependencies below remain relevant.

The atlas is **not wholly procedural**. `create_ground_detail_blender.py::atlas()` reads the existing project raster `ContentSource/Textures/Environment/textures/mesh_bark_basecolor.png`:

- `twig_bark` and `lichen_bark` reuse its sampled colour and luminance-derived surface information.
- `fence_wood` includes a small sampled-bark luminance contribution in base colour. Its current height/normal calculation omits that photographic luminance contribution and uses softened procedural grain.
- Other leaf/flower/wood-end regions are generated by the same deterministic atlas code. Planed wood and cut ends occupy different atlas cells.

The reused raster SHA256 recorded by `GroundDetail/atlas_regions.json` is `0b83bf19f803808759151d17c6361045c5e086a5b860018de2f5c29a5533754b`. The inspected project records do **not** establish that raster's original photographer, external URL or licence. Consequently this package does not claim CC0 status or independently cleared redistribution rights for that source. Preserve the existing project asset provenance and resolve it before distribution if it is not documented elsewhere.

The meadow directive's woodworking references informed part relationships (staves/hoops, hub/spokes/rim, axle/deck), not copied geometry or textures. No claim of historically exact medieval construction is made. External document illustrations were not incorporated into the atlas.

## Material and coordinate contract

The current runtime source maps are under `ContentSource/Textures/Environment/textures/`:

- `ground_detail_basecolor.png`: sRGB base colour.
- `ground_detail_normal.png`: runtime normal convention, UV V-down.
- `ground_detail_surface_ra.png`: R roughness, G ambient occlusion, B unused zero, A opaque 255.

Atlas size is 2048 × 2048, with 16 cells and 24 px edge padding per cell. All meshes use material slot 0, renderer material ordinal 15, texture layer 0. No alpha-cutout material or metallic wood is introduced. Plant leaves have explicit thin closed shells. The meshes are static; this package does not supply wind weights, physics or collision assets.

Blender uses metres, Z-up, local ground pivots and identity asset transforms. Engine export rotates `(x,y,z)` to `(x,z,-y)`; UV V is flipped before tangent calculation. Runtime normals/tangents are checked for finite unit length and perpendicularity; their recalculated handedness is preserved. FBX uses forward -Z, up Y, `FBX_SCALE_UNITS`, tangent export, one material and no animation. GLB uses Y-up, normals/tangents and embedded material export.

Blender material previews use `GroundDetail/FBXTextures/ground_detail_normal_opengl.png` (green channel flipped relative to the runtime map) and the separate roughness PNG. They are not byte-identical to the runtime normal/surface images. Older **GroundDetail** packed `.blend`/`.glb` files may contain the previous atlas; they are not evidence that the current runtime texture matches those older previews. The current source PNGs and regenerated v003 outputs are the applicable inputs.

Each plank receives deterministic seed-based UV cropping/offset and optional 180-degree rotation within `fence_wood`; no 90-degree grain rotation is used. Cut-end UVs are unchanged. Barrel staves receive analogous variation. LODs share procedural seeds; reduced topology and leaf counts still require engine LOD-transition review.

## Reproduction

Use the actual installed Blender executable. Run stages separately so the blockout and final images can be inspected before proceeding:

```powershell
$repo = 'C:/Users/crapa/.codex/worktrees/cpu-gpu-utilization/Project-HS'
& $blender --background --factory-startup --python "$repo/tools/art/create_meadow_props_blender.py" -- --root $repo --stage geometry
# Open preview_v003/blockout.png and inspect the source before finish.
& $blender --background --factory-startup --python "$repo/tools/art/create_meadow_props_blender.py" -- --root $repo --stage finish
& $blender --background --factory-startup --python "$repo/tools/art/create_meadow_props_blender.py" -- --root $repo --stage verify
& $blender --background --factory-startup --python "$repo/tools/art/create_meadow_props_blender.py" -- --root $repo --stage register
```

The script imports existing helpers without running their stage entry point. `finish` reuses existing atlas files; it does **not** regenerate them or call the older GroundDetail registration routine. If shared atlas inputs change, regenerate the atlas and its preview-map copies in a separate controlled operation, then rerun `finish` and `verify`. Preserve v003 or increment the version before a new art revision; rerunning these commands targets the current v003 filenames.

`geometry` creates a separate scene and refuses conflicting asset names rather than deleting unrelated objects. It asserts radius limits. `finish` writes the 21-record interchange file and validates topology/UV/tangent contracts. `verify` reopens the source, checks FBX dimensions and triangle counts, imports GLB and binds its success record to the SHA256 of `runtime_records.json`.

`register` requires that matching successful verification and exactly the 21 expected names. It upserts by name into `ContentSource/Models/Environment/environment_meshes.json`, preserves unrelated records and their order, saves a content-hash-named original backup, then uses a temporary file and atomic replacement. The registration manifest records script/input/output hashes and preserved-record hashes. A fixture check verified upsert, unchanged unrelated records, byte-identical repeated registration and refusal of stale verification. Registration alone does not build, cook or validate the game.

## Large generated files and version control

`verification/environment_meshes_before_578e81bd6ed78cdb.json` is a **100,408,352-byte** safety copy of the pre-registration environment registry. Keep it available for local recovery; it is not a new authoritative source and should not be added as another ordinary Git-tracked JSON copy. `runtime_records.json` is a **44,599,516-byte** generated interchange file duplicating the newly registered mesh values; its retention/tracking should follow the project's asset policy rather than being staged automatically. `.blend1` files are automatic Blender backups and the repository already ignores them.

The script, this README, source/verification manifests and intended final assets are the meaningful handoff. No cleanup or Git tracking change was performed while writing this note; old source versions and recovery data remain preserved.
