# 1. 최종 목표

Project-HS의 content build, runtime asset resolution, verification, render validation을 정확한 dependency와 명시적인 generation 중심으로 개편한다.

반드시 달성한다.

- 변경된 입력과 직접 관련된 expensive producer/build/test만 재실행한다.
- clean targeted verify가 stale generated file 없이 동작한다.
- Runtime/Test는 암묵적인 `Cooked/` 상태가 아니라 명시적인 Generation을 사용한다.
- 동일 source의 반복 scan/hash/decode를 제거한다.
- source-side validation을 CTest에서 반복하지 않되 generated product에 대한 독립 consumer validation은 유지한다.
- 동일 render baseline/GPU 초기화의 불필요한 반복을 제거한다.
- smoke/render 검증은 사용자 settings/profile과 독립적이다.
- CPU test는 병렬화하고 실제 GPU test는 직렬화한다.
- 사람, CI, AI가 동일한 dependency와 versioned evidence를 사용한다.
- 기존 determinism, source-hash 의미, replay/experiment, cooked ABI를 유지한다.

구조 변경 비용보다 correctness, 최종 incremental performance, reproducibility를 우선한다.

# 4. CMake toolchain

Project-HS 기준 CMake를 4.4.x 이상으로 올리고 초기 기준 binary는 4.4.3으로 고정한다.

먼저 repo-local launcher/bootstrap을 구현한다.

```text
bootstrap supported CMake
    ↓
checksum 검증
    ↓
CI / verify / developer command에서 같은 binary 사용
    ↓
cmake_minimum_required(VERSION 4.4)
```

현재 PATH에서 발견된 임의 `cmake`를 그대로 사용하는 방식을 제거한다.

CMake 4.5 전용 기능에는 의존하지 않는다.

Ninja generator를 유지한다.

# 5. 기존 build dependency 오류 수정

## `hs_content`

전역:

```cmake
add_dependencies(hs_content hs_shaders)
```

를 제거한다.

shader를 실제 소비하는 action 또는 packaging 단계만 shader output에 의존한다.

## `hs_combat_sim`

`--validate-only`는 cooked content 없이 실행 가능해야 한다.

실제 simulation execution만 `simulation_rules` product preparation을 요구한다.

## `hs_content_tools`

2026-10-21 경량화에서 실행 파일 자체를 제거했다. 빌드/실행 wrapper와 범용 JSON 숫자 편집기를 별도로 유지하지 않는다. 원본 JSON 편집, `hs_game_data --validate-only`, native producer/Generation 타깃과 직접 게임 실행을 사용한다.

## `hs_runtime_tests`

`particle_effects.hsbin` 등 실제 테스트에서 읽는 generated product를 명시적 test preparation dependency로 연결한다.

## `hs_runtime_assets`

always-out-of-date:

```text
add_custom_target(... ALL ...)
```

copy 구조를 제거한다.

shader, D3D12 DLL, PIX DLL, font 등은 실제 `OUTPUT` 기반 command로 만든다.

# 6. compile-time absolute path 제거

구형 `hs_content`/`hs_content_tools` binary는 제거됐다. 남은 GameData 제작기는 실행 파일 옆 `hs_build_config.json`의 source root를 사용하며 별도 CMake 실행 파일 경로는 보관하지 않는다.

대상 예:

```text
HS_GAME_DATA_DIRECTORY
HS_AUDIO_DIRECTORY
HS_CHARACTER_*
HS_MONSTER_*
HS_COOKED_DIRECTORY
HS_BINARY_DIRECTORY
HS_PROJECT_EXECUTABLE
HS_CONTENT_EXECUTABLE
```

source/build root와 tool path는 실행 argument 또는 build-time config로 전달한다.

ActionKey와 deterministic output에 physical checkout path가 들어가지 않게 한다.

서로 다른 worktree root에서 동일 source/recipe를 실행한 deterministic action은 동일 ActionKey와 ProductSetId를 가져야 한다.

# 9. Static / dynamic dependency

Static root dependency는 CMake에 선언한다.

실행 중 발견되는 dependency는 producer가 depfile에 기록한다.

예:

```text
audio_cues.json
      ↓
Audio producer
      ↓
실제 referenced WAV
      ↓
audio.d
      ↓
Ninja deps log
```

FBX material texture도 동일하다.

Dynamic dependency는 가능한 한 reference-driven으로 만든다.

광범위 `GLOB CONFIGURE_DEPENDS`를 실제 consumed dependency 대신 사용하지 않는다.

directory membership 자체가 의미 있는 입력이면 명시적인 manifest/inventory input으로 모델링한다.

# 10. CMake-visible asset output

Dynamic content action의 안정적인 CMake output은 `ActionResult`다.

예:

```text
Build/Actions/audio/result.json
Build/Actions/character.archer/result.json
```

실제 product:

```text
Build/Products/
    audio/<product-set-id>/...
    character.archer/<product-set-id>/...
```

`ProductSetId`는 실행 후 결정되므로 immutable product 경로를 configure-time `OUTPUT`으로 선언하지 않는다.

고정 output인 일반 build rule에는 이 제한을 적용하지 않는다.

# 11. Producer 간 scheduler edge

B가 A의 generated product를 소비하면 CMake dependency를 이전 immutable product path에 걸지 않는다.

```text

    DEPENDS A/result.json
```

B 실행 시:

```text

    ↓
현재 ProductSetId
    ↓
필요한 exact product
```

를 resolve한다.

B의 ActionKey에는 실제 사용한 upstream product identity가 포함된다.

# 12. ActionKey

ActionKey는 Ninja freshness key가 아니다.

```text
Ninja
    timestamp / depfile / missing output /
    command 및 build dependency를 보고 실행 결정

Producer
    dynamic dependency 발견
    digest 계산
    ActionKey 생성
```

ActionKey canonical 입력:

```text
action-key schema version

action id
recipe id
recipe version

static inputs:
    logical role/path
    content digest

dynamic inputs:
    logical role/path
    content digest

upstream generated product identity

output-affecting configuration
output-affecting external tool/platform identity
```

포함 금지:

```text
absolute checkout/build path
physical output path
mtime
timestamp
PID
machine name
duration
global legacy source_hash
output에 영향 없는 environment variable
```

용도:

```text
semantic identity
reproducibility
provenance
same-input/same-result check
why
향후 cache lookup
```

---

# 13. Recipe identity

변환 semantics를 소유하는 producer code가:

```text
recipe_id
recipe_version
```

을 소유한다.

CMake에 같은 version을 중복 선언하지 않는다.

외부 tool identity는 필요에 따라 포함한다.

```text
FBX SDK
DirectXTex
compression implementation
기타 실제 output-affecting tool
```

Builder executable 전체 hash를 무조건 모든 ActionKey에 포함하지 않는다.

동일 ActionKey가 다른 ProductSetId를 생성하면 recipe/tool identity 누락 또는 nondeterminism으로 보고 실패시킨다.

GPU encoder output이 hardware/driver에 따라 달라지는지는 실제 digest 비교로 검증한다. 차이가 확인되면 관련 environment identity를 ActionKey에 포함하거나 canonical deterministic encoder를 사용한다.

---

# 14. Product publication

Producer는 최종 product directory에 직접 쓰지 않는다.

기본 성공 경로:

```text
1. action-local staging directory 생성
2. products 생성
3. producer validation
4. product digest/size 계산
5. ProductSetId 계산
6. ProductSet namespace atomic publish
7. depfile 완성
8. deterministic ActionResult atomic publish
9. command success 반환
```

동일 ProductSetId가 이미 존재하면 bytes/integrity를 확인하고 재사용할 수 있다.

실패 또는 crash 중 incomplete ProductSet이 published namespace에 나타나서는 안 된다.

---

# 15. ProductSetId

ProductSetId는 canonical ordering한 다음 record에서 계산한다.

```text
logical product id
content digest
size
```

physical path는 제외한다.

같은 ProductSet namespace의 product는 in-place 수정하지 않는다.

# 16. ActionResult

모든 content producer는 deterministic `ActionResult`를 primary CMake output으로 생성한다.

필수 정보:

```text
schema_version

action_id
action_key

recipe_id
recipe_version

inputs:
    logical role/path
    digest

upstream product dependencies

product_set_id

products:
    logical id
    immutable locator/path
    digest
    size
```

canonical serialization을 사용한다.

내용이 기존 ActionResult와 같으면 다시 쓰지 않는다. 필요하면 temporary serialization 후 byte comparison/atomic replace한다.

다음은 넣지 않는다.

```text
timestamp
duration
machine
PID
비결정적 diagnostic
```

# 17. ActionExecutionReceipt

관찰/성능 정보는 ActionResult와 분리한다.

```text

start/end

```

이 파일은 downstream correctness dependency가 아니다.

`why`에서:


# 18. Missing/corrupt product repair

다음 상태를 감지한다.

```text
ActionResult 존재
product 누락/손상
```

Generation/Test preparation에서:

```text
existence
size
필요한 digest/integrity
```

를 확인한다.

기본 repair:

```text
1. action_id와 오류 code 보고
2. 해당 stable ActionResult invalidate
3. CMake/Ninja asset target build
4. producer 재실행
5. 새 ActionResult 검증
6. generation composition 재실행
```

Producer executable을 build system 밖에서 직접 호출해 repair하지 않는다.

# 19. Legacy hash streaming

관련:

```text
Source/Apps/Content/content_source_inventory.cpp
Source/Apps/Content/content_source_inventory.hpp
```

`gameplay_source_bytes`, `all_source_bytes`에 FBX/PNG/WAV 등을 통째로 누적하는 방식을 제거한다.

기존 FNV byte stream을 그대로 streaming 처리한다.

반드시 보존:

```text
source order
logical names
NUL/separator bytes
binary byte order
sort order
include/exclude rules
```

변경 전에 기존 구현과 신규 streaming 구현이 동일 hash를 내는 regression oracle을 만든다.

JSON parsing용 text만 보관하고 binary는 chunk hash 후 폐기한다.

prefix-FNV optimization은 최초 구현에 포함하지 않는다.

# 24. Environment

관련:


# 27. Shader와 runtime native assets

Shader는 현재 output-driven CMake/Ninja 구조를 유지한다.

HLSL include dependency를 가능한 한 실제 compiler dependency에 연결한다.

render artifact identity에는 실제 shader product identity를 포함한다.

D3D12/PIX/font copy도 고정 output command로 유지하고 always-run aggregate로 만들지 않는다.

# 28. Scoped Generation

Generation은 항상 full runtime을 의미하지 않는다.

동일 manifest schema로 scope별 exact subset을 지원한다.

예:

```text
runtime-full
test:runtime.integration
render:legacy
render:enhanced
```

또는 equivalent required-product capability를 사용한다.

Targeted test 하나 때문에 전체 character/environment/audio를 생성해서는 안 된다.

Generation completeness는:

> 해당 scope가 선언한 required product set이 완전함

을 의미한다.

manifest에 없는 product를 `Cooked/` 등에서 fallback해서는 안 된다.

---

# 29. GenerationId

GenerationId는 worktree-independent canonical semantics로 계산한다.

최소:

```text
generation schema version
scope 또는 canonical required-product set
logical product ids
product digests
product sizes
consumer semantics에 실제 필요한 generation-level identity
```

physical path/current-pointer path는 제외한다.

모든 scoped generation에 global legacy content hash를 무조건 넣지 않는다.

legacy identity가 해당 consumer contract에 필요하면 포함하고, 그렇지 않은 provenance는 별도 evidence/receipt에 둔다.

동일 GenerationId 아래 immutable manifest 내용이 달라지는 구조를 허용하지 않는다.

---

# 30. Generation Manifest와 publish

Generation Composer는 raw source를 읽지 않는다.

입력:

```text
required ActionResults
fixed build products
required logical product ids
```

각 product entry:

```text
logical id
immutable locator/path
digest
size
```

기본 publish:

```text
1. required products 준비
2. ActionResult/product integrity 확인
3. staging manifest 생성
4. scope completeness 검증
```

# 32. Product GC

immutable ProductSet을 도입하는 즉시 worktree-local GC를 제공한다.

roots:

```text

current published Generations
명시적으로 retained/pinned Generations
명시적 pins
```

일반 build/verify 실행 중 aggressive GC하지 않는다.

GC로 product가 사라져도 repair protocol로 재생성 가능해야 한다.
